# 밀리초 클릭 타이머

내 컴퓨터 시계와 서버 시계의 오차(skew), 그리고 클릭이 서버에 도착하기까지 걸리는 지연(latency)을
측정해서, 목표한 서버 시각(예: 정각 00.000)에 맞추려면 **내 컴퓨터 시계 기준으로 몇 시 몇 분 몇 초
몇 ms에 눌러야 하는지** 계산해주는 도구입니다.

## 구성 파일

- `index.html` — 실제로 여는 페이지 (계산기 + 실시간 카운트다운)
- `proxy_server.py` — 로컬 측정 프록시 (파이썬 표준 라이브러리만 사용, 추가 설치 불필요)
- `run_proxy.bat` / `run_proxy.sh` — 프록시를 더블클릭 한 번으로 실행하는 런처 (윈도우 / 맥·리눅스)

## 왜 프록시가 필요한가

대부분의 사이트는 브라우저 보안 정책(CORS) 때문에 `index.html`이 그 사이트에 직접 요청을 보내
응답을 읽을 수 없습니다. 반면 **서버끼리의 요청(같은 컴퓨터에서 실행하는 프로그램 → 사이트)은
이 제한이 없습니다.** 그래서 작은 로컬 프록시가 대신 요청을 보내고, 결과(서버 응답 시각, 걸린
시간)를 `index.html`에 돌려주도록 만들었습니다. 사용자가 오차/지연 값을 직접 알아내어 입력할
필요가 없습니다.

## 사용 방법

1. **프록시 실행 (최초 1회)**: `run_proxy.bat`(윈도우) 또는 `run_proxy.sh`(맥/리눅스)를
   더블클릭합니다. "로컬 측정 프록시 실행 중"이 뜨면 성공이며, 측정하는 동안 창을 닫지 않습니다.
   파이썬이 없다는 메시지가 뜨면 [python.org](https://python.org)에서 설치(설치 화면에서
   "Add python.exe to PATH" 체크) 후 다시 실행합니다.
2. **`index.html` 열기**: 더블클릭하거나 브라우저로 엽니다.
3. **1. 실제 사이트와 시간 동기화 측정**: "측정하고 싶은 실제 사이트 주소"에 원하는 URL(예:
   `https://weverse.io/`)을 입력하고, "프록시 연결 확인" → "측정 시작"을 누릅니다. 11회 측정 후
   자동으로 오차(skew)·지연(latency)이 계산됩니다.
4. **2. 목표 시각 설정**: 서버 기준으로 맞추고 싶은 시각(예: 다음 정각)을 입력합니다.
5. **3. 결과 확인**: "내 컴퓨터 시계로 OO시 OO분 OO초 OOOms에 클릭하세요"라는 안내가 표시됩니다.
6. **4. 실시간 카운트다운**: 큰 시계와 남은 시간이 표시되고, 목표 시각 근처(±50ms)에서 초록색으로
   강조됩니다.

프록시를 쓸 수 없는 환경이거나 이미 오차/지연 값을 알고 있다면, "수동 입력" 영역에 직접 입력해도
됩니다.

## 계산 공식

```
skew(ms)    = 서버 시각 - 내 시각         (양수면 서버 시계가 더 빠름)
latency(ms) = 클릭 → 서버 도착까지 걸리는 편도 시간

클릭할 내 시각 = 목표 서버 시각 - latency - skew
```

skew와 latency는 아래 방식(간이 NTP 방식)으로 측정합니다. 프록시는 브라우저와 같은 컴퓨터에서
실행되므로 시계 기준이 동일해, 프록시가 측정한 시각을 그대로 브라우저 계산에 사용할 수 있습니다.

- 프록시가 대상 사이트에 요청을 보내기 직전 시각 `t1`, 응답 받은 직후 시각 `t2`를 기록
- 응답의 `Date` 헤더에서 서버 시각 `Ts`를 읽음
- `RTT = t2 - t1`, `latency ≈ RTT / 2`
- `skew ≈ Ts - (t1 + t2) / 2`

여러 번 측정해 RTT가 가장 작은(=네트워크 흔들림이 가장 적은) 샘플들만 평균을 내어 정확도를
높입니다.

## 한계

- 네트워크 지연은 매번 흔들리기(jitter) 때문에 100% 정확하게 0ms에 맞추는 것은 불가능합니다.
  이 도구는 "가장 유리한 평균적인 타이밍"을 알려주는 보조 수단입니다.
- 측정은 가벼운 요청(페이지 1회 조회) 기준이라, 실제 "제출" 동작이 서버에서 더 무거운 처리를
  거친다면(로그인 확인, 재고 체크 등) 실제 지연은 더 클 수 있습니다. 특히 사람이 몰리는 순간에는
  서버 처리 시간이 평소보다 크게 늘어날 수 있는데, 이는 사전에 예측할 수 없습니다.
- 브라우저 타이머/화면 갱신 자체에도 수~수십 ms의 오차가 있을 수 있습니다.
- 대상 사이트가 봇 차단(WAF)으로 프록시의 요청 자체를 막을 수도 있습니다. 이 경우에도 수동 입력
  모드를 사용할 수 있습니다 (브라우저 개발자 도구 Network 탭에서 해당 사이트 응답의 `Date` 헤더와
  요청 왕복 시간을 직접 확인해 입력).
