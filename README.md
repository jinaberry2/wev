# 밀리초 클릭 타이머

내 컴퓨터 시계와 서버 시계의 오차(skew), 그리고 클릭이 서버에 도착하기까지 걸리는 지연(latency)을
측정해서, 목표한 서버 시각(예: 정각 00.000)에 맞추려면 **내 컴퓨터 시계 기준으로 몇 시 몇 분 몇 초
몇 ms에 눌러야 하는지** 계산해주는 도구입니다.

브라우저에서 `index.html`을 열면 바로 사용할 수 있습니다 (별도 설치/빌드 불필요).

## 사용 방법

1. **시간 동기화 측정**: CORS가 허용된 시간 API(기본값: worldtimeapi.org)에 11회 요청을 보내
   서버와 내 컴퓨터 사이의 시간 오차와 편도 지연을 추정합니다. 측정이 막히면(CORS 오류 등) 직접
   오차/지연 값을 입력하는 수동 모드를 사용하세요.
2. **목표 시각 설정**: 서버 기준으로 맞추고 싶은 시각(예: 다음 정각)을 입력합니다.
3. **결과 확인**: "내 컴퓨터 시계로 OO시 OO분 OO초 OOOms에 클릭하세요"라는 안내가 표시됩니다.
4. **실시간 카운트다운**: 큰 시계와 남은 시간이 표시되고, 목표 시각 근처(±50ms)에서 초록색으로
   강조됩니다.

## 계산 공식

```
skew(ms)    = 서버 시각 - 내 시각         (양수면 서버 시계가 더 빠름)
latency(ms) = 클릭 → 서버 도착까지 걸리는 편도 시간

클릭할 내 시각 = 목표 서버 시각 - latency - skew
```

skew와 latency는 아래 방식(간이 NTP 방식)으로 측정합니다.

- 요청 보내기 직전 내 시각 `t1`, 응답 받은 직후 내 시각 `t2`를 기록
- 응답에 담긴 서버 시각 `Ts`를 읽음
- `RTT = t2 - t1`, `latency ≈ RTT / 2`
- `skew ≈ Ts - (t1 + t2) / 2`

여러 번 측정해 RTT가 가장 작은(=네트워크 흔들림이 가장 적은) 샘플들만 평균을 내어 정확도를
높입니다.

## 한계

- 네트워크 지연은 매번 흔들리기(jitter) 때문에 100% 정확하게 0ms에 맞추는 것은 불가능합니다.
  이 도구는 "가장 유리한 평균적인 타이밍"을 알려주는 보조 수단입니다.
- 브라우저 타이머/화면 갱신 자체에도 수~수십 ms의 오차가 있을 수 있습니다.
- 실제로 클릭하려는 사이트가 CORS를 허용하지 않으면 자동 측정이 동작하지 않습니다. 이 경우
  수동 입력 모드를 사용하세요 (예: 브라우저 개발자 도구 Network 탭에서 해당 사이트 응답의
  `Date` 헤더와 요청 왕복 시간을 직접 확인해 입력).
